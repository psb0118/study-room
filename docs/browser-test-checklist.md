# 여섯 기능 브라우저 테스트 절차

이 문서는 공부 일정 알림, 로컬 일정 알림, 계획 카드 집중 타이머, 밀린 계획
정리, JSON 복원, 주간 회고를 **실제 브라우저에서 직접 클릭하며** 확인하는
절차입니다.

> **테스트 계정을 따로 사용하세요.** 실제 학습 데이터가 있는 계정에서 JSON
> 복원을 시험하면 같은 ID의 데이터가 덮어써질 수 있습니다.

## 빠른 경로

알림 대기 시간을 빼고 아래 순서로 보면 약 15분이면 전체 흐름을 확인할 수
있습니다.

`1 알림 모드` → `3-A 집중 타이머 중간 종료` → `4 밀린 계획` →
`5 JSON 내보내기·복원` → `6 주간 회고` → `2 로컬 알림`

2번은 계획 시작 시각을 기다려야 하므로 마지막에 하거나, 테스트 중 다른
기능을 먼저 확인한 뒤 알림 시각에 맞춰 돌아옵니다.

## 0. 공통 준비

### 환경

- 대상: `https://psb0118.github.io/study-room/`
  - 로컬에서 확인하려면 `npm run dev` 후 표시되는 주소를 사용합니다.
- 브라우저: 최신 Chrome 또는 Edge 데스크톱
- 화면: 데스크톱 너비, 브라우저 확대 100%
- 계정: 학생 역할의 **테스트 계정**
  - 기존 계정을 쓰지 말고 새 이메일로 회원가입하거나, 테스트 전용 계정을
    사용합니다.
  - 로그인 화면의 **회원가입**에서 이름·이메일·비밀번호를 입력한 뒤 역할
    선택에서 **학생**을 고릅니다. 이메일 가입이 막혀 있으면 Google 로그인을
    사용합니다.
- 네트워크: 온라인
- Firestore 규칙: 저장소의 최신 `firebase/firestore.rules`가 배포되어 있어야
  계획·과목·기록 저장과 JSON 가져오기가 정상 동작합니다.

### 알림 권한

1. Chrome 주소창 왼쪽의 사이트 정보 아이콘을 엽니다.
2. **알림**이 **허용**인지 확인합니다.
3. 운영체제의 방해 금지 모드·집중 모드를 끕니다.
4. 알림을 처음 켤 때 브라우저 권한 팝업이 뜨면 **허용**을 누릅니다.

권한을 이미 거부했다면 사이트 설정에서 **알림 → 허용**으로 바꾼 뒤 페이지를
새로고침합니다.

### 현재 빌드의 알림 모드

이 저장소의 기본 빌드는 `VITE_FCM_VAPID_KEY`가 없으면 **로컬 알림 모드**로
동작합니다.

| 빌드 상태 | 일정 시작 알림 카드 | 실제 동작 |
|---|---|---|
| VAPID 키 없음 | `서버 준비 중` → `로컬 알림 켜짐` | 앱을 열어둔 동안만 알림 |
| VAPID 키 있음 + Functions 배포 | `꺼짐` → `기기 등록 필요` → `일정 알림 켜짐` | 앱을 닫아도 서버 알림 |

테스트 중 카드에 표시된 상태를 먼저 기록해 두세요. VAPID 키가 있는 빌드라면
**2번 로컬 알림 테스트** 대신 **1-B 서버 알림 확인**을 수행합니다.

### 테스트용 데이터 만들기

학생 계정으로 로그인한 뒤 아래 데이터를 만듭니다.

1. **과목 관리 → ＋ 과목 추가**
   - 과목명: `브라우저 테스트`
   - 색상: 아무 색이나 선택
   - **과목 추가** 클릭
2. **공부 계획 → ＋ 계획 추가**로 어제 날짜의 계획 두 개를 만듭니다.
   - 계획 B: 제목 `밀린 계획 B`, 날짜 **어제**, 목표 `10분`, 상태 `예정`
   - 계획 C: 제목 `밀린 계획 C`, 날짜 **어제**, 목표 `20분`, 상태 `예정`
3. 알림 테스트용 계획은 **2번 테스트 직전에** 따로 만듭니다. 미리 만들면
   시작 시각이 지나 버릴 수 있습니다.

> 날짜를 어제로 바꾸려면 계획 모달의 **날짜** 입력을 사용합니다.
> 계획 저장은 모달 아래 **계획 추가** 버튼으로 완료합니다.

## 1. 알림 준비 상태와 로컬 알림 켜기

**확인할 것:** 서버가 준비되지 않아도 일정 알림 카드가 깨지지 않고, 로컬
알림 모드로 전환할 수 있는가?

### 절차

1. 학생 계정으로 로그인합니다.
2. 왼쪽 메뉴에서 **주간 목표**를 엽니다.
3. 화면 아래의 **일정 시작 알림** 카드를 찾습니다.
4. VAPID 키가 없는 빌드라면 다음을 확인합니다.
   - 상태 배지: `서버 준비 중`
   - 설명: `지금은 알림 서버 준비 중이라 앱을 열어둔 동안만 동작합니다.`
   - `일정 시작 알림 받기` 체크박스가 활성화되어 있음
5. `일정 시작 알림 받기`를 클릭합니다.
6. 브라우저 권한 팝업이 뜨면 **허용**을 누릅니다.
7. 다음을 확인합니다.
   - 초록색 안내: `앱을 열어둔 동안 일정 알림을 켰어요. 서버 알림은 준비 중이에요.`
   - 상태 배지: `로컬 알림 켜짐`
8. 페이지를 새로고침한 뒤 **주간 목표**로 돌아와 설정이 유지되는지 확인합니다.

### 기대 결과

- [ ] `서버 준비 중` 또는 `로컬 알림 켜짐`이 표시된다.
- [ ] 알림 권한을 허용하면 체크박스가 켜진다.
- [ ] 새로고침 후에도 `로컬 알림 켜짐`이 유지된다.
- [ ] `알림 시점`을 `시작 시각`으로 바꾸면 저장 안내가 표시된다.

### 실패 시 확인

- 브라우저 알림 권한이 `denied`인지 확인합니다.
- 시크릿 창에서는 알림이 제한될 수 있으므로 일반 창에서 테스트합니다.
- 콘솔에 오류가 있으면 Firestore 규칙과 네트워크를 확인합니다.

### 1-B. VAPID 키가 있는 빌드라면

1. 같은 카드에서 상태가 `꺼짐`인지 확인합니다.
2. `일정 시작 알림 받기`를 클릭하고 권한을 허용합니다.
3. 기기 등록이 끝나면 `일정 알림 켜짐`으로 바뀌는지 확인합니다.
4. 이 모드는 Functions와 Blaze 요금제가 준비되어야 실제 서버 발송까지
   확인할 수 있습니다. 서버 발송은 **앱을 완전히 닫은 뒤** 시작 시각에
   알림이 오는지로 확인합니다.

## 2. 앱을 열어둔 동안 일정 시작 로컬 알림

**확인할 것:** 계획 시작 시각에 로컬 알림이 한 번 오고, 새로고침해도 같은
알림이 중복되지 않는가?

> 현재 시각이 자정 전후 5분 이내라면 날짜가 바뀌지 않도록 잠시 후 테스트를
> 시작하세요. 계획 날짜는 **오늘**이어야 합니다.

### 절차

1. **공부 계획 → ＋ 계획 추가**를 엽니다.
2. 다음 값으로 저장합니다.
   - 과목: `브라우저 테스트`
   - 제목: `알림 테스트`
   - 날짜: 오늘
   - 목표 공부 시간: `1분`
   - 시작 시간: **현재 시각 + 3분** (같은 날짜여야 함)
   - 상태: `예정`
3. **주간 목표**로 이동합니다.
4. `일정 시작 알림 받기`가 켜져 있는지 확인합니다.
5. `알림 시점`이 **`시작 시각`**인지 확인합니다.
   - `5분 전`으로 되어 있으면 3분 뒤 테스트가 즉시 지나가므로 반드시
     `시작 시각`으로 바꿉니다.
6. 이 탭을 닫지 말고 시작 시각까지 기다립니다.
7. 알림이 표시되면 스크린샷을 남깁니다.
8. 알림이 온 직후 페이지를 새로고침하고, 같은 알림이 다시 오지 않는지
   5분 정도 관찰합니다.

### 기대 결과

- [ ] 시작 시각에 운영체제 알림이 표시된다.
- [ ] 제목: `하루결 공부 알림`
- [ ] 본문에 `알림 테스트`와 시작 시각이 포함된다.
- [ ] 새로고침해도 같은 계획의 알림이 중복 표시되지 않는다.
- [ ] 계획이 `완료` 상태이거나 시작 시간이 비어 있으면 알림이 오지 않는다.

### 확인 팁

DevTools → **Application → Session Storage**에서
`haru-gyeol-plan-notice:`로 시작하는 키를 확인할 수 있습니다. 알림이 한 번
발생하면 해당 계획의 키가 저장됩니다.

### 실패 시 확인

- 브라우저 사이트 권한이 **허용**인지 확인합니다.
- 운영체제 알림 센터와 방해 금지 모드를 확인합니다.
- 탭을 백그라운드로 보내지 말고 열어둡니다.
- 시작 시각이 이미 5분 넘게 지나지 않았는지 확인합니다.
- Console에서 `Notification.permission`이 `granted`인지 확인합니다.
- 앱을 닫으면 로컬 알림은 동작하지 않습니다. 이는 정상이며, 서버 알림은
  VAPID 키와 Functions 배포 후에 확인합니다.

## 3. 공부 계획 카드에서 집중 타이머 시작

**확인할 것:** 계획 카드의 `집중` 버튼으로 타이머가 열리고, 중간 종료와
완주 모두 공부 기록으로 저장되는가?

### 3-A. 중간에 그만하기

1. **공부 계획**으로 이동합니다.
2. `알림 테스트` 계획 카드에서 **집중** 버튼을 클릭합니다.
3. 모달 제목이 `집중 타이머`인지 확인합니다.
4. 초기 상태가 `준비됨`, 버튼이 `집중 시작`인지 확인합니다.
5. **집중 시작**을 누릅니다.
6. 10초 정도 기다린 뒤 **일시정지**를 눌러 타이머가 멈추는지 확인합니다.
7. **그만하기**를 누릅니다.
8. 저장 안내가 표시될 때까지 기다립니다.

### 기대 결과

- [ ] 모달에 과목과 계획 제목이 표시된다.
- [ ] `집중 시작` 후 상태가 `집중 중`으로 바뀌고 시간이 줄어든다.
- [ ] `그만하기` 후 `1분 집중을 기록했어요. 계획은 아직 완료 전이에요.`가
      표시된다.
- [ ] **공부 기록** 화면에 `집중 타이머 · 알림 테스트` 기록이 보인다.
- [ ] 계획 상태는 `예정` 또는 `진행 중`으로 남아 있다.

### 3-B. 1분 완주해서 계획 완료

1. 목표 시간이 `1분`인 새 계획 `타이머 완주 테스트`를 오늘 날짜로 만듭니다.
2. 계획 카드의 **집중**을 누릅니다.
3. **집중 시작**을 누르고 1분을 기다립니다.
4. 타이머가 0이 될 때까지 기다립니다.

### 기대 결과

- [ ] `1분 집중을 기록하고 계획을 완료했어요.`가 표시된다.
- [ ] 계획 카드 상태가 `완료`로 바뀐다.
- [ ] **공부 기록**에 1분 기록이 추가된다.
- [ ] **통계**의 총 공부 시간과 주간 회고에 기록이 반영된다.

### 실패 시 확인

- `집중` 버튼은 학생 화면에만 표시됩니다. 부모 화면에서는 보이지 않는 것이
  정상입니다.
- 기록 저장에 실패하면 Firestore 규칙과 네트워크를 확인합니다.
- 모달을 닫을 때 저장하지 않은 기록이 있으면 확인창이 뜨는지도 확인합니다.

## 4. 밀린 계획을 오늘로 옮기기

**확인할 것:** 어제의 미완료 계획을 개별적으로 또는 한 번에 오늘로 옮길 수
있는가?

### 절차

1. **공부 계획**으로 이동합니다.
2. 어제 만든 계획 B와 C가 보이는지 확인합니다.
3. 화면 위쪽에 `2개의 밀린 계획이 있어요.` 배너가 표시되는지 확인합니다.
4. 계획 B 카드의 **오늘로** 버튼을 클릭합니다.
5. 계획 B의 날짜가 오늘로 바뀌고, 배너의 숫자가 `1개`로 줄어드는지
   확인합니다.
6. 배너의 **모두 오늘로** 버튼을 클릭합니다.
7. 계획 C도 오늘로 이동하고 배너가 사라지는지 확인합니다.
8. 기간 필터를 **오늘**로 바꿔 두 계획이 모두 표시되는지 확인합니다.

### 기대 결과

- [ ] 배너의 밀린 계획 수가 실제 미완료 계획 수와 일치한다.
- [ ] 개별 `오늘로`가 해당 계획만 이동한다.
- [ ] `모두 오늘로`가 남은 밀린 계획을 한 번에 이동한다.
- [ ] 완료된 과거 계획은 밀린 계획으로 세지 않는다.
- [ ] 이동 후 새로고침해도 날짜가 오늘로 유지된다.

### 추가 확인

어제 날짜의 `완료` 계획을 하나 만들고, 그 계획이 배너 숫자와 `모두 오늘로`
대상에 포함되지 않는지 확인합니다.

## 5. JSON 백업 내보내기와 복원

**확인할 것:** 내보낸 JSON으로 과목·계획·기록을 복원하고, 프로필·가족
연결·포인트는 건드리지 않는가?

### 5-A. 백업 만들기

1. 왼쪽 메뉴에서 **부모님 연결**을 엽니다.
2. 화면 아래 **데이터 관리** 카드로 이동합니다.
3. **JSON으로 내보내기**를 클릭합니다.
4. 다운로드된 파일 이름이 `haru-gyeol-...json`인지 확인합니다.
5. 파일을 텍스트 편집기로 열어 다음을 확인합니다.
   - `"app": "하루결"`
   - `"version": 1`
   - `subjects`, `plans`, `records` 배열이 존재
   - 현재 테스트 계정의 계획과 기록 개수가 포함됨

### 5-B. 복원 확인

1. **공부 계획**에서 `밀린 계획 B`의 제목을 `복원 전 수정`으로 바꿉니다.
2. 필요하면 계획 하나를 삭제해 복원 대상이 생기게 합니다.
3. **부모님 연결 → 데이터 관리**로 돌아갑니다.
4. **JSON 가져오기**를 클릭합니다.
5. 방금 내보낸 JSON 파일을 선택합니다.
6. 확인창의 문구를 확인합니다.
   - `과목 N개, 계획 N개, 기록 N개를 가져올까요?`
   - `같은 ID의 데이터는 덮어씁니다. 프로필 정보는 가져오지 않아요.`
7. 확인을 누릅니다.
8. `N개 항목을 가져왔어요. 화면에 반영되는 것을 확인해 주세요.` 안내를
   확인합니다.
9. **공부 계획**에서 `복원 전 수정`이 원래 제목으로 돌아왔는지 확인합니다.
10. **공부 기록**에서 내보내기 전 기록이 복원되었는지 확인합니다.

### 5-C. 잘못된 파일 거부 확인

1. 아무 텍스트 편집기로 `invalid.json`을 만들고 아래처럼 저장합니다.

   ```json
   { "app": "다른 앱", "version": 1 }
   ```

2. **JSON 가져오기**에서 이 파일을 선택합니다.
3. 데이터가 바뀌지 않고 다음 오류가 표시되는지 확인합니다.
   - `하루결 JSON 백업 파일이 아니에요.`

### 기대 결과

- [ ] JSON 다운로드와 파일명이 정상이다.
- [ ] 복원 확인창에 과목·계획·기록 개수가 표시된다.
- [ ] 같은 ID의 계획 제목이 백업 시점으로 돌아온다.
- [ ] 삭제한 계획·기록이 복원된다.
- [ ] 프로필 이름·역할·가족 연결·포인트는 변경되지 않는다.
- [ ] 잘못된 JSON은 오류를 보여주고 기존 데이터를 바꾸지 않는다.

### 주의

- **JSON 가져오기** 버튼은 학생 본인 계정의 데이터 관리 화면에만 표시됩니다.
  부모 화면이나 부모가 선택한 자녀 데이터 화면에서는 보이지 않는 것이
  정상입니다.
- 복원은 전체 초기화가 아니라 같은 ID를 덮어쓰고 새 ID를 추가하는 방식입니다.
- 테스트 후에는 테스트 계정에서 계획·기록·과목을 정리하거나, 테스트 전용
  계정을 삭제합니다.

## 6. 주간 회고 카드

**확인할 것:** 이번 주 완료율·공부 시간·연속 학습·최다 과목·이어갈 계획이
실제 데이터와 일치하는가?

### 절차

1. **통계**로 이동합니다.
2. 화면 위쪽의 **이번 주 회고** 카드를 찾습니다.
3. 표시된 주간 범위가 이번 주 월요일부터 일요일까지인지 확인합니다.
   - 완료율은 그중 **오늘까지 마감된 계획**만 대상으로 계산됩니다.
4. 다음 값을 확인합니다.
   - 완료 표시: `완료 계획 수 / 오늘까지 마감된 이번 주 계획 수`
   - 완료율
   - 이번 주 공부 시간
   - 연속 학습 일수
   - 가장 많이 공부한 과목과 시간
   - 다음 주로 이어갈 계획 목록
5. **공부 계획**에서 오늘까지 날짜가 지난 이번 주 계획 수와 완료 계획 수를
   직접 세어 카드와 비교합니다. 미래 날짜 계획은 완료율 분모에서 제외됩니다.
6. **공부 기록**에서 이번 주 기록의 시간 합계를 확인해 카드의 공부 시간과
   비교합니다.
7. 기간 탭을 `오늘`, `주`, `월`로 바꿔도 주간 회고 카드가 **이번 주 기준**으로
   유지되는지 확인합니다.
8. 이번 주에 미완료 계획이 있으면 `다음 주로 이어갈 계획`에 최대 3개가
   표시되는지 확인합니다.

### 기대 결과

- [ ] 완료율과 완료 계획 수가 오늘까지 마감된 계획 데이터와 일치한다.
- [ ] 이번 주 공부 시간이 기록 합계와 일치한다.
- [ ] 최다 과목이 기록이 많은 과목과 일치한다.
- [ ] 미완료 계획이 `다음 주로 이어갈 계획`에 표시된다.
- [ ] 기록이 없으면 `아직 기록이 없어요`가 표시된다.
- [ ] 놓친 계획이 없으면 `이번 주 놓친 계획이 없어요.`가 표시된다.
- [ ] 기간 탭을 바꿔도 주간 회고의 기준 주간은 바뀌지 않는다.

### 실패 시 확인

- 주간 회고는 `plans`와 `records` 원본을 기준으로 계산됩니다.
- 계획 상태를 `완료`로 바꾼 뒤 잠시 기다려 Firestore 동기화를 확인합니다.
- 기록 시간이 0인 기록은 통계에 의미 있게 반영되지 않을 수 있습니다.

## 7. 마무리·증빙

### 테스트 후 정리

1. 테스트 계정에서 `브라우저 테스트` 과목과 테스트 계획을 삭제합니다.
2. **공부 기록**에서 테스트 기록을 삭제합니다.
3. 필요하면 브라우저 사이트 설정에서 알림 권한을 초기화합니다.
4. 테스트 계정을 계속 사용할 경우 로그아웃합니다.

### 증빙으로 남길 것

- 각 기능의 통과/실패 스크린샷
- 알림이 표시된 시각과 계획 시작 시각
- JSON 파일 이름과 복원 전후 계획 개수
- 실패 시 DevTools Console의 오류와 Network의 실패 요청
- 브라우저 이름·버전, 운영체제, VAPID 키 유무

### 자동화로 확장할 때

이 절차는 로그인·알림 권한·운영체제 알림 센터가 필요한 수동 테스트를
전제로 합니다. 나중에 Playwright로 자동화하려면 별도 테스트 계정의 로그인
상태를 저장하고, 알림은 브라우저 권한과 타이머 대기 시간을 제어할 수 있는
환경에서 실행해야 합니다. 현재 저장소에는 브라우저 E2E 도구가 포함되어
있지 않습니다.
